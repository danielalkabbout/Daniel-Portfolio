# Putting the portfolio online (free)

| Piece | Where | Cost |
| --- | --- | --- |
| Database | Neon, `production` branch (Frankfurt) | Free |
| API (.NET 10) | Render web service from `render.yaml` | Free |
| Website (React) | Cloudflare Pages, built from `web/` | Free |
| Images, bot check | Cloudflare R2 and Turnstile | Free |
| AI for Echo | Google AI Studio (Gemini) | Free tier |
| Request emails | Resend | Free tier |

Do the steps in order. Anything marked **optional** can be skipped and added later; the feature
simply stays off until its value is set.

---

## Phase 6: API and database

### 1. Neon production connection string
1. Neon console > your project > **Connect**.
2. Branch: **production**. Turn **Connection pooling** off. Format: **.NET**.
3. Copy the string. This is a password: paste it only into Render, never into the repo or a chat.

### 2. Studio password hash (laptop)
```
cd daniel-portfolio/api
dotnet run --project src/Portfolio.Api -- hash-password
```
Keep the printed hash for step 3. Use a different password from your laptop one if you like.

### 3. Render
1. render.com > **New** > **Blueprint** > choose `danielalkabbout/Daniel-Portfolio`.
2. Render reads `render.yaml` and asks for each value:

| Key | Value |
| --- | --- |
| `ConnectionStrings__Default` | the Neon string from step 1 |
| `Admin__Email` | `danielalkabbout@gmail.com` |
| `Admin__PasswordHash` | the hash from step 2 |
| `Cors__Origins__0` | `https://daniel-portfolio.pages.dev` (the Pages address from step 4; edit it later if Cloudflare gives a different one) |
| `Gemini__ApiKey` | optional, from aistudio.google.com > Get API key |
| everything else | leave empty for now, filled in during Phase 7 |

`Jwt__Key` is generated by Render automatically.

3. Press **Apply**. The first build takes a few minutes. On first start the API creates the
   tables and adds your content by itself.
4. Check `https://daniel-portfolio-api.onrender.com/health` says **Healthy**, and
   `https://daniel-portfolio-api.onrender.com/api/content` returns your content.
   (If Render picked a different name, use the address shown on the service page.)

On the free plan the API sleeps after 15 minutes without visitors and takes about a minute to wake.
The website never waits for it: it shows the content baked in at build time and refreshes quietly.

## Phase 7: website and the extras

### 4. Cloudflare Pages
1. dash.cloudflare.com > **Workers & Pages** > **Create** > **Pages** > **Connect to Git** > pick the repo.
2. Project name: `daniel-portfolio`. Production branch: `main`.
3. Build settings:

| Setting | Value |
| --- | --- |
| Framework preset | None |
| Root directory | `web` |
| Build command | `npm run build` |
| Build output directory | `dist` |

4. Environment variables (Production):

| Name | Value |
| --- | --- |
| `NODE_VERSION` | `22` |
| `VITE_API_URL` | `https://daniel-portfolio-api.onrender.com` |

5. **Save and deploy**. The site goes live at `https://daniel-portfolio.pages.dev`.
   If the address is different, update `Cors__Origins__0` on Render to match.

### 5. Publish button (deploy hook)
1. Pages project > **Settings** > **Builds** > **Deploy hooks** > add one named `studio`, branch `main`.
2. Copy the URL into Render as `Pages__DeployHookUrl`.

Now **Publish changes** in the studio also rebuilds the site with the new content baked in.

### 6. Turnstile bot check (optional)
1. Cloudflare > **Turnstile** > **Add widget**. Hostname: `daniel-portfolio.pages.dev`. Mode: Managed.
2. Site key: add to Pages as `VITE_TURNSTILE_SITE_KEY`, then **Retry deployment** on the latest build.
3. Secret key: add to Render as `Turnstile__Secret`.

### 7. Image uploads with R2 (optional)
Without R2, screenshots you upload in the studio are stored inside the content itself, which works
but makes it heavier.
1. Cloudflare > **R2** > **Create bucket** `portfolio-media`.
2. Bucket > **Settings** > **Public access** > enable the **r2.dev** URL. Copy it.
3. R2 overview > **Manage API tokens** > **Create API token**: Object Read & Write, only this bucket.
4. Add to Render:

| Key | Value |
| --- | --- |
| `R2__AccountId` | your Cloudflare account ID (R2 overview page) |
| `R2__AccessKeyId` | from the token |
| `R2__SecretAccessKey` | from the token |
| `R2__Bucket` | `portfolio-media` |
| `R2__PublicBaseUrl` | the r2.dev URL from step 2 |

### 8. Email when a request arrives (optional)
1. resend.com > **API Keys** > create one.
2. Add to Render: `Email__ResendApiKey` = the key, `Email__To` = the address you signed up to Resend with.

### 9. Keep the API awake (optional)
GitHub repo > **Settings** > **Secrets and variables** > **Actions** > **Variables** > new variable
`API_URL` = `https://daniel-portfolio-api.onrender.com`. The **Keep the API awake** workflow then
pings it every 14 minutes from 06:00 to midnight Lebanon time.

---

## Final check
- Open the site, wait for Echo, ask it something unusual (uses the AI if the Gemini key is set).
- Send yourself a test request from the Services page, then see it in `/admin` > **Requests**.
- In `/admin`, change one small thing, **Publish changes**, and confirm the site shows it.

Every change in Render's environment variables restarts the API by itself. After changing a
Pages variable, redeploy the latest build so it takes effect.
